# OpenLEO Fundamentals

This is the shortest study path for understanding OpenLEO v0.1. It teaches only the
concepts that the current program actually uses. The external references are optional:
use them when a lesson remains unclear, not as required reading.

## How to use this course

Complete one lesson per sitting. Each should take roughly 25 minutes:

1. Read the explanation.
2. Follow the worked OpenLEO example.
3. Open the named source and test.
4. Run the focused test command.
5. Answer the checkpoints without looking back.
6. Complete the tiny exercise and compare your result with the answer.

From the repository root, after completing the README installation step, generate the
reference run:

```bash
uv sync --locked --group dev
uv run openleo run examples/scenarios/iss_cartagena.json --output runs/iss
```

Keep these files open while studying:

- [`examples/scenarios/iss_cartagena.json`](../examples/scenarios/iss_cartagena.json)
- `runs/iss/trace.csv`, generated by the command above
- `runs/iss/summary.json`, generated by the command above

Study now:

1. SI units and decibels.
2. GP/OMM orbital data and SGP4.
3. Time, frames, and ground-station geometry.
4. Range rate, delay, and Doppler.
5. The free-space receiver chain and theoretical capacity.
6. Verification, validation, and reproducibility.

Defer until the feature exists: atmospheric propagation, uncertainty distributions,
MODCOD, routing, ns-3, dashboards, and 3D globes.

## Lesson 1 — SI units and decibels

### The question

How can a radio link combine huge gains and losses without manipulating enormous or
tiny linear numbers at every step?

### Five terms

- **SI unit:** a standard unit such as metre, second, hertz, watt, or kelvin.
- **dB:** a logarithmic ratio; it is not an absolute power.
- **dBW:** power relative to one watt.
- **dBm:** power relative to one milliwatt.
- **dBi:** directional antenna gain relative to an ideal isotropic antenna.

OpenLEO includes units in names like `range_m`, `carrier_frequency_hz`, and
`eirp_dbw`. Those suffixes are part of the scientific safety system.

Logarithms turn multiplication into addition and division into subtraction. This lets
the receiver equation become a readable list of gains and losses.

### Formulas

$$
G_{dB}=10\log_{10}\left(\frac{P_2}{P_1}\right)
$$

$$
P_{dBW}=10\log_{10}(P_W), \qquad P_{dBm}=P_{dBW}+30
$$

### Worked OpenLEO example

The frozen scenario declares:

- EIRP: `10 dBW`
- receiver gain: `20 dBi`
- miscellaneous loss: `2 dB`

Interpretation:

- `10 dBW` is `10 W`.
- `20 dBi` represents a gain factor of $10^{20/10}=100$ in the stated direction.
- A `2 dB` loss retains $10^{-2/10}=0.630957$, about 63.1% of the power.

These are synthetic assumptions, not measurements of ISS or Cartagena equipment.

### See it in OpenLEO

- Scenario: [`radio_link`](../examples/scenarios/iss_cartagena.json)
- Source: [`received_carrier_power_dbw()`](../src/openleo/physics.py)
- Proof: [`test_reference_receiver_chain`](../tests/test_physics.py)

```bash
uv run pytest tests/test_physics.py::test_reference_receiver_chain -q
```

### Explain it back

1. What is the difference between `dB`, `dBW`, and `dBi`?
2. Does adding 10 dB mean adding 10 watts?
3. Why do OpenLEO variable and column names include units?

### Exercise

At closest sampled approach, received carrier power is `-124.805877641 dBW`.
Convert it to dBm and watts.

#### Answer

- dBm: $-124.805877641+30=-94.805877641\,\mathrm{dBm}$
- watts: $10^{-124.805877641/10}=3.3068\times10^{-13}\,\mathrm{W}$

Checkpoint answers:

1. `dB` is a ratio, `dBW` is absolute power relative to 1 W, and `dBi` is directional
   antenna gain relative to an isotropic antenna.
2. No. A 10 dB power increase multiplies power by ten.
3. To make incompatible quantities harder to mix silently.

## Lesson 2 — GP data, OMM, and SGP4

### The question

What does the frozen orbital CSV represent, and why can it not be propagated as a
simple Kepler orbit?

### Five terms

- **GP data:** general perturbations mean elements prepared for an analytical model.
- **OMM:** Orbit Mean-Elements Message, a standard field vocabulary for mean elements.
- **SGP4:** the matching propagation model used with these public elements.
- **Epoch:** the instant around which an element set is most representative.
- **Element age:** requested time minus element epoch.

The CSV is not a table of future spacecraft positions. It contains one fitted set of
mean elements and metadata. Its familiar-looking orbital values are not ordinary
osculating Keplerian elements. Using a two-body solver would therefore produce a
different and incorrect trajectory for this data product.

Important fields:

- `MEAN_MOTION`: revolutions per day.
- `ECCENTRICITY`: orbit-shape parameter; zero is circular.
- `INCLINATION`: orbital-plane tilt.
- `RA_OF_ASC_NODE`, `ARG_OF_PERICENTER`, `MEAN_ANOMALY`: orientation and phase.
- `BSTAR`: an SGP4 fitting parameter, not a direct atmospheric measurement.

Accuracy generally degrades away from the epoch. OpenLEO's 14-day warning is a
quality warning, not an accuracy guarantee.

### Formulas

$$
T_{minutes}=\frac{1440}{n_{rev/day}}
$$

$$
age_{days}=\frac{t-epoch}{86400\,\mathrm{s}}
$$

### Worked OpenLEO example

The frozen ISS record contains:

- epoch: `2026-08-30T11:57:48.556224Z`
- mean motion: `15.48938909 rev/day`
- inclination: `51.6316°`
- eccentricity: `0.00050266`

Approximate orbital period:

$$
1440/15.48938909=92.9669\,\mathrm{minutes}
$$

The scenario begins `0.238756438 days`, or `5.73015 hours`, before the element epoch.
The negative signed age means “before the epoch,” not “invalid.”

### See it in OpenLEO

- Data: [`iss_2026-08-30.csv`](../examples/data/iss_2026-08-30.csv)
- Source: [`load_orbit()`](../src/openleo/orbit.py)
- Proof: [`test_load_orbit_accepts_frozen_gp_record`](../tests/test_simulation.py)

```bash
uv run pytest tests/test_simulation.py::test_load_orbit_accepts_frozen_gp_record -q
```

### Explain it back

1. Is an OMM-compatible record a sequence of measured positions?
2. Why does OpenLEO use SGP4 rather than a simple two-body model?
3. What does a negative element age mean?

### Exercise

The scenario stop age is `-0.231811993 days`. How many hours before the epoch is it?

#### Answer

$$
0.231811993\times24=5.56349\,\mathrm{hours}
$$

Checkpoint answers:

1. No. It is a fitted set of mean elements and metadata.
2. The elements were fitted for SGP4 and are not ordinary osculating elements.
3. The requested propagation instant is earlier than the epoch.

## Lesson 3 — Time, frames, and topocentric geometry

### The question

Why is a satellite position meaningless unless its time and coordinate frame are both
known?

### Five terms

- **UTC:** civil time scale used at OpenLEO's public boundary.
- **TEME:** the frame associated with SGP4 output.
- **ITRS/ECEF:** coordinates rotating with Earth.
- **WGS84:** the Earth ellipsoid used for the ground station.
- **Topocentric ENU:** local east–north–up coordinates seen from the station.

The v0.1 frame chain is:

```text
OMM-compatible mean elements
        ↓ SGP4
TEME spacecraft state at a UTC instant
        ↓ Skyfield frame transformation
Earth-fixed spacecraft and WGS84 station
        ↓ subtraction and local rotation
east / north / up → azimuth / elevation / slant range
```

Azimuth is clockwise from north. Elevation is upward from the local horizon. Slant
range is the direct distance from station to spacecraft. Elevation is not spacecraft
altitude above Earth.

UTC includes leap seconds. TAI is continuous atomic time, TT is TAI plus 32.184 seconds,
and UT1 follows Earth rotation. You do not convert these manually in v0.1; Skyfield
does the time work and OpenLEO fingerprints the builtin leap-second table.
OpenLEO accepts ordinary ISO 8601 `Z` timestamps; do not enter a literal leap-second
value with seconds equal to `60`.

### Formulas

$$
\boldsymbol{\rho}_{ECEF}=\mathbf r_{sat,ECEF}-\mathbf r_{station,ECEF}
$$

$$
\rho=\sqrt{E^2+N^2+U^2}
$$

$$
elevation=\sin^{-1}(U/\rho), \qquad azimuth=atan2(E,N)\bmod360^\circ
$$

### Worked OpenLEO example

The Cartagena station is at `37.6057°` latitude, `-0.9913°` longitude, and `20 m`
WGS84 height.

At `2026-08-30T06:18:50Z`, OpenLEO reports:

- azimuth: `38.6743°`
- elevation: `61.5800°`
- slant range: `473,676.7193 m`

The ISS is high in the north-eastern sky. Its zenith distance is
$90^\circ-61.5800^\circ=28.4200^\circ$.

The pass uses a 10° elevation mask. Sampled AOS and LOS are the first and last
10-second grid samples meeting that mask; they are not interpolated continuous-time
crossings.

### See it in OpenLEO

- Time boundary: [`_utc()`](../src/openleo/input.py)
- Geometry: [`simulate_scenario()` and `_row_at()`](../src/openleo/simulation.py)
- Proof: [`test_closest_approach_topocentric_geometry_matches_independent_enu`](../tests/test_simulation.py)

```bash
uv run pytest tests/test_simulation.py::test_closest_approach_topocentric_geometry_matches_independent_enu -q
```

### Explain it back

1. Why can a station ECEF vector not be subtracted directly from an untransformed TEME
   spacecraft vector?
2. What directions do azimuths 0°, 90°, 180°, and 270° represent?
3. Why are timezone-aware UTC timestamps required?

### Exercise

Using the closest sample above, calculate its zenith distance and describe its viewing
direction.

#### Answer

- zenith distance: `28.4200°`
- viewing direction: north-east and high above the horizon

Checkpoint answers:

1. Their axes belong to different frames.
2. North, east, south, and west.
3. Geometry depends on the exact instant and Earth orientation; an ambiguous time can
   rotate the station to the wrong location.

## Lesson 4 — Range rate, delay, and Doppler

### The question

How does relative station–spacecraft motion change arrival time and received frequency?

### Five terms

- **Slant range:** direct station-to-spacecraft distance.
- **Range rate:** rate at which that distance changes.
- **Radial velocity:** relative velocity projected onto the line of sight.
- **Propagation delay:** one-way signal travel time.
- **Doppler shift:** received-frequency change caused by radial motion.

Range rate is not the spacecraft's full orbital speed. Only the line-of-sight component
changes range.

OpenLEO's convention is:

- negative range rate: approaching;
- positive range rate: receding;
- approaching: positive downlink Doppler;
- receding: negative downlink Doppler.

v0.1 models nominal first-order, one-way Doppler. It is not a two-way tracking
observable or a relativistic precision model.

### Formulas

$$
\tau=\frac{\rho}{c}
$$

$$
\dot\rho=\frac{\boldsymbol\rho\cdot\dot{\boldsymbol\rho}}{\rho}
$$

$$
\Delta f=-f_c\frac{\dot\rho}{c}
$$

where $c=299,792,458\,\mathrm{m/s}$.

### Worked OpenLEO example

At sampled AOS:

- range: `1,495,209.6389 m`
- range rate: `-6,709.8042 m/s`
- carrier: `2.2 GHz`

Delay:

$$
1,495,209.6389/299,792,458=0.0049874825\,\mathrm{s}=4.98748\,\mathrm{ms}
$$

Doppler:

$$
-(2.2\times10^9)(-6709.8042)/299,792,458\approx+49,239.3\,\mathrm{Hz}
$$

The spacecraft is approaching, so range rate is negative and downlink frequency shifts
upward.

### See it in OpenLEO

- Source: [`propagation_delay_s()` and `doppler_shift_hz()`](../src/openleo/physics.py)
- Assembly: [`_row_at()`](../src/openleo/simulation.py)
- Proof: [`test_frozen_pass_geometry_has_consistent_range_rate_and_doppler_signs`](../tests/test_simulation.py)

```bash
uv run pytest tests/test_simulation.py::test_frozen_pass_geometry_has_consistent_range_rate_and_doppler_signs -q
```

### Explain it back

1. Why is range rate normally smaller than total spacecraft speed?
2. Why does approaching produce positive Doppler in OpenLEO?
3. Why can the closest sampled row still have a small non-zero range rate?

### Exercise

For range `1,000,000 m`, carrier `2.2 GHz`, and receding range rate `+6,000 m/s`,
calculate delay and Doppler.

#### Answer

- delay: `0.003335640952 s`, or `3.33564 ms`
- Doppler: `-44,030.4606 Hz`, approximately `-44.03 kHz`

Checkpoint answers:

1. Range rate is only the projection of relative velocity onto the line of sight.
2. The Doppler formula has a minus sign and approaching range rate is negative.
3. The 10-second sampling grid need not contain the exact continuous-time minimum.

## Lesson 5 — Free-space loss, receiver noise, and capacity

### The question

How does OpenLEO turn distance and synthetic radio assumptions into a theoretical
information-rate ceiling?

### Five terms

- **EIRP:** transmitter power combined with transmit-direction antenna gain.
- **FSPL:** geometric free-space spreading loss.
- **Noise density:** thermal noise power per hertz.
- **C/N₀:** carrier power relative to noise density.
- **SNR:** carrier power relative to noise across the chosen bandwidth.

The chain is:

```text
EIRP + receiver gain
        − FSPL
        − miscellaneous loss
        = received carrier power
        ↓ compare with kT noise density
      C/N₀
        ↓ include channel bandwidth
       SNR
        ↓ Shannon–Hartley equation
theoretical capacity upper bound
```

`C/N0` uses noise per hertz. SNR uses noise across the channel bandwidth. Shannon
capacity assumes ideal coding and is not modem rate, packet goodput, or measured
throughput.

### Formulas

$$
\begin{aligned}
L_{FSPL}&=20\log_{10}\left(\frac{4\pi\rho f}{c}\right)\\
C_{dBW}&=EIRP+G_{rx}-L_{FSPL}-L_{misc}\\
N_{0,dBW/Hz}&=10\log_{10}(kT_{sys})\\
C/N_0&=C_{dBW}-N_{0,dBW/Hz}
\end{aligned}
$$

$$
SNR_{dB}=C/N_0-10\log_{10}(B)
$$

$$
C_{max}=B\log_2\left(1+10^{SNR_{dB}/10}\right)
$$

### Worked OpenLEO example

The focused receiver-chain test uses:

- EIRP: `10 dBW`
- receiver gain: `20 dBi`
- path loss: `161 dB`
- miscellaneous loss: `2 dB`
- system temperature: `200 K`
- channel bandwidth: `1 MHz`

OpenLEO obtains:

- received carrier: $10+20-161-2=-133\,\mathrm{dBW}$
- noise density: `-205.588867217 dBW/Hz`
- `C/N0`: `72.588867217 dB-Hz`
- SNR: `12.588867217 dB`

In the complete frozen pass, the closer `473,676.7193 m` sample reaches a larger
`6,336,955.324 bit/s` upper bound. The allowed interpretation is: “approximately
6.337 Mbit/s theoretical upper bound under synthetic free-space assumptions.”

- Source: [`physics.py`](../src/openleo/physics.py)
- Proof: [`test_reference_receiver_chain`](../tests/test_physics.py)
- Full-pass proof: [`test_simulate_scenario_reproduces_frozen_pass`](../tests/test_simulation.py)

```bash
  tests/test_physics.py::test_shannon_bound_at_zero_db_snr_equals_bandwidth \

```

### Explain it back

1. How much additional FSPL does doubling range produce?
2. What is the difference between `C/N0` and SNR?
3. Does `6.337 Mbit/s` predict real ISS throughput?

### Exercise

Repeat the reference chain after increasing EIRP from `10 dBW` to `13 dBW`. Calculate
the new carrier power, `C/N0`, and SNR. All other values remain unchanged.

#### Answer

- carrier: $13+20-161-2=-130\,\mathrm{dBW}$
- `C/N0`: $-130-(-205.588867)=75.588867\,\mathrm{dB\,Hz}$
- SNR: $75.588867-10\log_{10}(10^6)=15.588867\,\mathrm{dB}$

Each logarithmic carrier metric rises exactly 3 dB. The Shannon bound rises
non-linearly because it is calculated after converting SNR back to a linear ratio.

Checkpoint answers:

1. $20\log_{10}(2)=6.0206\,\mathrm{dB}$.
2. `C/N0` compares with noise density per hertz; SNR includes bandwidth.
3. No. It uses synthetic RF values, free-space propagation, and an ideal information
   theory limit.

## Lesson 6 — Verification, validation, and reproducibility

### The question

What do passing tests and matching checksums prove—and what do they not prove?

### Five terms

- **Verification:** did we implement the stated rules and equations correctly?
- **Regression check:** did a known software result unexpectedly change?
- **Physical validation:** does the model agree sufficiently with independent reality?
- **Reproducibility:** can someone repeat the result with the same inputs and method?
- **SHA-256:** a fingerprint of exact file bytes.

A matching checksum proves byte identity, not scientific correctness. Likewise, 100%
test success would not prove that the synthetic RF assumptions represent an actual ISS
link.

OpenLEO preserves frozen inputs, SHA-256 fingerprints, sources, retrieval times,
dependency versions, deterministic outputs, limitations, and numeric tolerances.

### Formulas

$$
h=SHA256(\text{file bytes})
$$

$$
\dot\rho_{FD}\approx\frac{\rho_{i+1}-\rho_{i-1}}{2\Delta t}
$$

$$
|x_{computed}-x_{reference}|\leq\epsilon
$$

### Worked OpenLEO example

The frozen orbit SHA-256 is:

```text
ddb21d9a4a3a4812ee397751555b9d55d2767f30c33190afba90e4bbb8db13f9
```

Near closest approach, adjacent ranges are:

- previous: `478,628.235728 m`
- next: `479,363.356214 m`
- separation between those samples: `20 s`

Finite-difference range rate:

$$
(479363.356214-478628.235728)/20=36.7560243\,\mathrm{m/s}
$$

Skyfield reports `37.1481223 m/s`. The difference is `0.392098 m/s`, inside the
declared `0.5 m/s` tolerance. This checks the range-rate implementation independently,
but it is still not comparison with a calibrated observation.

### Exercise

Predict what happens if the scenario text changes from `"step_s": 10.0` to
`"step_s": 1e1`.

#### Answer

Both values parse as `10.0`, so the physical trace should remain unchanged. The raw
scenario bytes differ, so its SHA-256 and recorded provenance change.

Checkpoint answers:

1. No. Tests verify the stated implementation and internal consistency.
2. That the file bytes match the expected bytes, not that their scientific contents
   are true.
3. Reproduction repeats a computation; physical validation compares it with independent
   observations.
